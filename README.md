# 鸡哥解题

Windows 桌面端「搜题」小工具：**后台常驻一个悬浮窗**，按快捷键截图 → 自动识别题目 → 流式输出解答。
支持文字输入解题两种入口，引擎可在「本机 Ollama（离线免费）」与任意「OpenAI 兼容云端服务」之间切换。

---

## 一、功能一览

| 能力 | 说明 |
|---|---|
| 截屏解题 | 全局热键（默认 `Ctrl+Alt+Q`）→ 鼠标框选题目区域 → 松开即自动解答；`Esc` 取消；回车/双击直接整屏 |
| 文字解题 | 悬浮窗内粘贴题目，`Ctrl+Enter` 或点「解答」 |
| 悬浮窗 | 无边框、可拖拽、可置顶、可一键收起成「像素小鸡」果冻悬浮球（带弹性动效），位置与状态自动记忆 |
| 系统托盘 | 双击显示；右键菜单可立即截图 / 历史 / 设置 / 退出 |
| 流式输出 | 答案边生成边显示，完成后用 Markdown 重排（标题、列表、加粗） |
| 历史记录 | 列表 + 搜索，可回看题干、原截图与完整解答，支持单条删除与全部清空 |
| 数据可清理 | 所有数据集中在一个 `data/` 目录，带「双向对账」机制，**不产生孤儿文件** |
| 多引擎可切换 | Ollama / 通义千问 / 智谱 GLM / DeepSeek / OpenAI / 自定义兼容接口，内置「测试连接」 |
| 模型一键检测 | 点「检测本机模型」列出服务端已装模型、点选即填；模型名对不上时**提前拦下并弹出修复按钮** |
| 解答风格可选 | 悬浮窗上直接切「只看答案 / 详细题解」。只看答案只给结果，**实测快 30 倍以上**（0.3s vs 10.1s） |
| 速度优化 | 模型预热 + 模型常驻显存，避免每次提问都等冷启动（冷启动实测 70-90 秒，热态 5-15 秒） |

## 二、环境要求

- Windows 10 / 11
- Python 3.10 及以上（仅用于创建虚拟环境；程序本体的依赖会装进项目内的 `.venv`）
- 一个可用的答题引擎（见第四节，二选一）

## 三、快速开始（三步）

1. **双击 `安装依赖.cmd`** —— 自动创建 `.venv` 并安装 PySide6 / pynput / httpx（首次约 1~3 分钟）。
   脚本最后会**真的 import 一遍**这三个包来验收（`deps ok: x.y.z`），而不是只看 pip 的退出码；
   它不会盲目升级 pip，所以不会出现「装到一半 pip 反而没了」的情况。
2. **双击 `启动鸡哥解题.cmd`** —— 用 `pythonw` 启动，不会留下黑框命令行窗口。
3. **右键任务栏托盘图标 → 设置** —— 配置答题引擎，点「测试连接」确认可用。

> 想验证环境是否正常：双击 `自检.cmd`，会跑 99 + 96 项自动化检查，不需要联网、不需要模型。
> 想连真实模型一起验收：双击 `完整自检.cmd`，四套共 239 项。第 4 套需要本机 Ollama + 视觉模型，
> 没启动它会直接说明并以退出码 2 结束（汇总里能看到），不会谎报成功。

命令行方式（调试时用，能看到日志输出）：

```bat
.venv\Scripts\python.exe main.py
```

## 四、首次必须做的配置：选一个答题引擎

打开「设置 → 引擎」，两个方向任选其一。

### 方案 A：纯离线（推荐，免费、不联网）

1. 安装并启动 [Ollama](https://ollama.com)。
2. 拉取一个**视觉模型**（截屏解题必需）：

   ```bat
   ollama pull qwen2.5vl:7b
   ```

   > 约 6 GB。显存吃紧可换更小的视觉模型，如 `qwen2.5vl:3b`。
3. 设置页里：服务商 = 「本机 Ollama（离线免费）」，API Key 留空。
4. **点「模型名」右边的「检测本机模型」** —— 程序会把你这台机器上真正装好的模型列出来，点选即可填入。
   > 预设里默认写的 `qwen2.5vl:7b` 是**通用推荐值，不代表你机器上已经拉下来了**。
   > 如果模型名和服务端实际有的对不上，请求会直接失败（程序会提前拦下来并列出你已装的模型）。
   > 界面上「模型名」不放心也可以手动填，格式是 `名字:tag`，例如 `qwen3.5:9b`。
5. 点「测试连接」，看到「连接成功」即可。

> **关于「额外请求参数」**：选本机 Ollama 时会自动填上 `{"think": false}`，**建议保持默认不要删**。
> Ollama 上的 Qwen3 / QwQ 这类**思考型（thinking）模型**，如果开着思考模式，输出预算会被内部推理过程吃光，
> 表现为「答案空白」或「只输出一半就断」。关掉它既能避免空答案，也明显更快。
> 走云端服务商时这个字段留空即可（通义可填 `{"enable_thinking": false}`，智谱可填 `{"thinking": {"type": "disabled"}}`）。
> 另外本机 Ollama 默认走**原生 `/api/chat` 协议**而不是 `/v1` 兼容端点——实测兼容端点对思考型模型会返回空内容。
> 如果服务商是其它需要兼容端点的本地推理框架（vLLM / LM Studio / Xinference 等），把「接口协议」改成 `OpenAI 兼容` 即可。
>
> **手改 `data\config.json` 的注意事项**：「接口协议」只认 `openai` 和 `ollama_native` 两个值，
> 手打错一个字母程序会**自动纠正回该服务商的预设值**（不纠正的话会静默落到兼容端点，
> 在本机 Ollama 上表现为「没有答案也不报错」，最难排查）。
> 而「额外请求参数」写坏不会静默纠正，会在测试/解答时直接抛中文错误提示你改。
> 另外首次启动时程序会写出一份默认 `config.json`，方便直接查看或手工修改。
> 其中 `answer_style` 只认 `brief`（只看答案）和 `detailed`（详细题解），
> `system_prompt` **留空表示按 `answer_style` 自动套内置提示词**，填了则完全覆盖风格。

### 方案 B：云端（识别数学公式/图表效果更好，需联网 + 付费）

服务商下拉框里选，然后填你自己的 API Key：

| 服务商 | 默认模型 | 支持图片 |
|---|---|---|
| 阿里通义千问（百炼） | `qwen-vl-max-latest` | 是 |
| 智谱 GLM | `glm-4v-flash` | 是（有免费额度） |
| OpenAI | `gpt-4o-mini` | 是 |
| DeepSeek | `deepseek-chat` | **否，只能文字解题** |

API Key 也可以不写进配置文件，改用环境变量 `JIGE_API_KEY` 提供（程序检测到环境变量时不会把 Key 落盘）。

## 五、怎么用

**截屏解题（核心流程）**

1. 任何界面下按 `Ctrl+Alt+Q`，屏幕会冻结并压暗。
2. 拖拽鼠标框住题目，松开 → 自动开始解答；框选时再按一次热键或按回车 = 整屏；`Esc` = 取消。
3. 悬浮窗会弹出并流式显示解答，可点「复制」拿走，或点「重解」重跑一次。

**文字解题**：悬浮窗切到「文字解题」标签，粘贴题目，`Ctrl+Enter`。

**收起/展开**：点标题栏的 `—` 收起成果冻悬浮球（不挡视线），点圆球恢复。
球的交互全是软的：

| 操作 | 反应 |
|---|---|
| 鼠标悬停 | **先挤压再弹起**（纵向拉长过冲一下），并保持放大 + 发光 |
| 右键单击 | 抖一下（振幅逐次衰减，自己停） |
| 左键按住 | 压扁，松手回弹 |
| 什么都不做 | 轻轻呼吸 |
| 按住拖动 | 移动位置（拖拽中会捏扁作反馈）。判定用**相对按下点的累计位移**，所以慢拖也不会被误当成「点击展开」 |

**改热键**：设置 → 热键与截屏 → 点输入框直接按组合键。必须包含修饰键（Ctrl/Alt/Shift）+ 一个普通键。

**切换解答风格**：悬浮窗右上角的「只看答案 / 详细题解」下拉，或设置 → 引擎 → 解答风格。

- **详细题解**：先讲知识点，再给完整步骤，最后给结论。适合学习、需要过程。
- **只看答案**：只给最终结果，整个回答一行。适合对答案、刷题。
- 切换会立即生效并记进配置，历史记录里每条都会标明当时用的哪种。

## 六、速度：先搞清楚慢在哪

本机模型的耗时由三段组成，本工程对三段都做了处理：

| 环节 | 实测耗时 | 处理方式 |
|---|---|---|
| 模型加载（权重读进显存） | **70-90 秒** | 启动时后台预热 + 模型常驻显存（见下） |
| 读题（图片/题干的 token 处理） | 1-6 秒 | 有缓存后极快；图片可调压缩宽度 |
| 生成答案（**主要变量**） | 0.3-15 秒 | 「只看答案」把输出压到一行，直接砍掉大头 |

同一台机器、同一个 9B 模型、同一道题的实测对拍：

```
详细题解   10.1 秒   输出 678 字
只看答案    0.3 秒   输出   7 字   ← 快了 30 倍以上
```

所以**想要快，第一件事就是切「只看答案」**，其次才是调参数。

**① 模型常驻显存（默认已开）**

Ollama 默认 5 分钟不用就把模型卸载，下次提问要重新把权重读进显存 —— 实测就是那 70-90 秒。
本程序默认按 `keep_alive: 30m` 请求，让模型留 30 分钟；设置 → 引擎 → 「模型驻留」可改（5 分钟 / 30 分钟 / 2 小时 / 常驻不卸载）。

> 这个字段是 Ollama 原生协议独有的。如果「接口协议」被改成「OpenAI 兼容」，它不会生效，
> 此时请改用系统环境变量 `OLLAMA_KEEP_ALIVE=30m`（设完重启 Ollama）。
> 显存紧张（比如 8G 显卡跑 9B 模型）就调小或设回 5 分钟。

**② 启动预热（默认已开）**

程序启动后会用后台线程向本机 Ollama 发一个**不含题目、不生成任何 token** 的请求，把模型提前读进显存。
这样你配好设置后第一次提问就不用干等。预热失败只写日志，绝不影响启动。

**③ 截图送模型的压缩宽度**

图片占用的 token 数与像素面积成正比，1600px 宽大约是 1024px 宽的 2.4 倍。
设置 → 热键与截屏 → 「送模型前压缩宽度」：`1024` 最快 / `1600` 均衡（默认）/ `2000+` 更清晰但明显更慢。
题目字号小、公式多的就调大。

**④ 其他可调项**

- 「最大输出」直接决定上限；「只看答案」会自动封顶到 512，不会超过你设的值。
- 换更小的模型（如 3B/7B）对速度的影响通常比任何参数调优都大。
- 冷启动那 70-90 秒是**把权重从磁盘读进显存**的代价；显存不够时（如 9B 模型配 8G 显卡）还会有一部分走内存，会更慢。换更小的模型或加显存最有效。

## 七、数据与清理（不会留孤儿文件）

所有持久化数据都在**一个目录**里：

```
E:\鸡哥解题\data\
├── config.json     配置（含 API Key，环境变量提供时不写这里）
├── app.db          历史记录索引（SQLite，WAL 模式）
├── app.db-wal/-shm SQLite 临时文件
├── app.lock        单实例锁
├── shots\          截图原图（PNG，文件名带时间戳 + 随机串）
└── logs\           滚动日志（单文件上限 1 MB，自动保留 3 份）
```

程序**不会**写注册表，也不会往 `%APPDATA%`、用户目录或别的地方塞文件。

**「无孤儿文件」的四道防线**（`app/store.py`）：

1. **先落盘图片、再写数据库记录**，任何一步失败都会回滚删除图片；
2. **双向对账**（启动时自动跑一次，设置页也能手动触发）：
   - 磁盘上有图片但数据库没有记录 → 删除该图片；
   - 数据库有记录但图片已丢失 → 清空引用、保留答案文本；
3. **删除记录时连带删除它的截图**，清空历史时一并清空 `shots/`；
4. **历史上限自动裁剪**（默认 500 条），超出部分连同截图一起删除，删完执行 `VACUUM` 回收磁盘空间。

**想彻底清干净**：设置 → 数据与清理 → 点「清空全部历史与截图」→ 再删除 `data` 文件夹即可。
（删 `data` 前请先退出程序，否则 `app.log` / `app.db` 正被占用。）

**数据库会平滑升级**：新增字段（例如记录「当时用的是只看答案还是详细题解」）会在启动时自动 `ALTER TABLE` 补上，
老记录一律回落到「详细题解」，不需要你手工迁移，也不会丢历史。

## 九、怎么扩展维护

| 想做的事 | 改哪里 |
|---|---|
| 加一个服务商 | `app/engine/presets.py` 里加一条（base_url / model / wire_api / vision），UI 与引擎自动识别 |
| 支持一种新协议 | 在 `app/engine/` 新建 Provider 继承 `BaseProvider`，覆写 `url` / `payload` / `iter_text` 三个钩子，再到 `service.py` 注册 |
| 改界面配色/圆角 | `app/ui/theme.py`，所有颜色集中在那里 |
| 改悬浮球的质地/动效 | 底色与高光在 `theme.paint_jelly_body()`（光晕单独在 `paint_jelly_halo()`，**不参与形变**）；球心的像素小鸡是 `theme.PIXEL_CHICK`（16×16 字符画）+ `paint_pixel_chick()`；弹性参数在 `app/ui/jelly.py` 顶部一组常量里 |
| 改解答风格 | 设置页的「系统提示词」，或 `app/config.py` 的 `DEFAULT_SYSTEM_PROMPT` |
| 改默认热键/截屏方式 | 设置页，或 `app/config.py`（注意热键必须写成 `<ctrl>+<alt>+q` 这种规范格式） |

## 十、自检与调试

```bat
完整自检.cmd                                        :: 四套全跑（一键，推荐用这个）
自检.cmd                                            :: 只跑离线的两套（核心 99 + 界面 96）
.venv\Scripts\python.exe tools\verify_live.py       :: 真机验证热键触发与应用启动（16 项）
.venv\Scripts\python.exe tools\verify_real_model.py :: 真实模型端到端（28 项，需 Ollama）
.venv\Scripts\python.exe tools\render_preview.py    :: 渲染界面预览图到 _verify\
```

四套加起来 **239 项**检查。**改完引擎相关代码，建议至少跑一次 `verify_real_model.py`** ——
假服务永远返回正常响应，所以「自检全绿」并不等于接真模型能用（空答案那类问题只有真模型才暴露）。
`verify_real_model.py` 的 28 项覆盖：文字题（兼容 + 原生两种协议）、图片题、
**真实抓屏 → 按 scale 换算裁切 → 送模型**、完整应用流程落库与界面渲染、
**「只看答案 / 详细题解」真实对拍与模型预热**。

`render_preview.py` 会把 9 张界面图渲染到 `_verify\`（主窗 / 截图页 / 收起态 / 设置三页 / 历史页 / 框选遮罩 / 果冻球各状态），
用于肉眼验收观感。该目录已在 `.gitignore` 里，看完随时可删。

日志在 `data\logs\app.log`；未捕获异常会被写进来（带完整堆栈）。

两种会显示 `SKIP` 的情况（**都不是应用问题**）：

- `verify_live.py` 在带「批量删除守卫」的沙箱环境下，两项清理检查会标 `SKIP` 并提示人工清理；
- **应用正在运行时**（对这个常驻托盘工具来说是常态）再跑 `verify_live.py`：`main.py` 有单实例保护，
  新实例会立刻以退出码 1 退出，而**那个分支不写日志**。脚本会先读 `data\app.lock` 探测到这一点，
  把启动测试整体标成 `SKIP`，而不是报一个查不出原因的 `FAIL`。想跑完整启动测试就先退出应用。

## 十一、常见问题

**1. 按了快捷键没反应**
被别的软件占用了（`Ctrl+Alt+Q` 和部分输入法、QQ、截图工具会冲突）。设置 → 热键与截屏里换一个组合，必须「修饰键 + 普通键」。也可能是热键被关掉了，勾上「启用全局热键」。

**2. 提示「无法连接本机服务」**
Ollama 没启动。先在终端跑 `ollama serve` 或打开 Ollama 客户端，再点「测试连接」。程序对 `127.0.0.1` 会强制绕过系统代理，所以代理不会影响本机调用。

**3. 提示「没有找到模型 xxx」**
服务端没有这个模型。两种可能：
- **本机 Ollama**：预设里的 `qwen2.5vl:7b` 只是通用推荐值，**你机器上不一定装过**。点「模型名」右边的**「检测本机模型」**，直接选一个已经有了的；或先 `ollama pull qwen2.5vl:7b`。
- **云端服务**：模型名要和该服务商的叫法一致（如通义是 `qwen-vl-max-latest`，不是 `qwen-vl-max`）。

程序会在「测试连接」时**提前拦下**这种情况，并把服务端实际已有的模型列出来，同时**直接弹出「检测本机模型」按钮**——
点一下就能换成你机器上已有的模型，不用自己去设置页里找。

**4. 截屏解题报错，但文字解题正常**
当前模型不支持图片。Ollama 需要视觉模型（如 `qwen2.5vl:7b`）；DeepSeek 目前没有视觉模型，只能文字解题。

**5. 截出来的题目识别不准**
框小一点，只框题干文字区域，别把选项、页眉、桌面图标一起框进去。

**6. 安装依赖失败**
换镜像重试（把 index 换成国内源）：

```bat
.venv\Scripts\python.exe -m pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple
```

> **别用清华源排查这类问题**：实测在部分网络下清华镜像会对 pip 返回 **HTTP 403**，
> 而同一个 URL 用 `curl` 却是 200，所以报错看着像「包不存在 / Python 版本不兼容」（典型症状是 `from versions: none`），
> 极容易带偏方向。判断方法：加 `-vvv` 看有没有 `403`。安装脚本默认走的是官方源 `pypi.org`，一般不需要换。

**7. 启动时提示「程序已经在运行」**
单实例保护生效了，去右下角托盘找图标，双击显示悬浮窗。若确认没有在运行（比如上次被强杀），删掉 `data\app.lock` 再启动。

**8. 解答一直空白，或者只输出一半就断**
两种情况：
- **思考型模型没关思考模式**（最常见）。用 Qwen3 / QwQ 这类模型时，内部推理会把输出预算吃光。设置 → 引擎 → 「额外请求参数」检查是否为 `{"think": false}`；如果被清空了，重新选一次服务商「本机 Ollama」即可自动填回。
- **`max_tokens` 太小**。默认 2048，按需要调到 4096 或更大。程序检测到最终答案为空时，会直接报错并给出这条提示，不会静默显示空白。

**9. 太慢了 / 每次第一次提问要等一分多钟**

先看「六、速度」那一节。按收益排序：

1. **切「只看答案」** —— 输出从 678 字变成 7 字，实测 10.1s → 0.3s，这是最大的杠杆。
2. **第一次提问特别慢**（70-90 秒）是模型冷启动，不是卡住了。程序默认已开「预热 + 模型驻留 30 分钟」，正常情况下你打开程序后它就悄悄把模型读进显存了；若你隔了很久再提问，或者把「模型驻留」设得过短，就会重新加载。
3. 换更小的模型（3B/7B）、把「送模型前压缩宽度」调小。
4. 显存不够会让模型部分走内存，那是最慢的一种情况 —— 8G 显卡跑 9B 模型就会这样。

**10. 切了「只看答案 / 详细题解」但回答没变化**

你在设置里填了**自定义系统提示词**。自定义的优先级高于风格开关（悬浮窗上会给出黄色提示，设置页的提示词框下方也会写明「当前生效」的是哪一份）。把那个框清空即可恢复由风格决定。

## 十二、已知限制（请先了解再使用）

- **不内置 OCR**：截图直接交给视觉模型，所以截屏解题依赖视觉模型；用纯文本模型时截屏解题不可用。
- **思考型模型必须关掉思考模式**：Qwen3 / QwQ 等若沿用它默认的思考模式，经 Ollama 会返回空内容或半截内容，程序已默认关闭（`{"think": false}`），改用其它框架时请在「额外请求参数」里自行关闭。
- **公式是「可读近似」不是排版**：`\frac{a}{b}` → `(a)/(b)`、`\sqrt{2}` → `√(2)`、`x_1` → `x₁`，复杂矩阵/积分上下限仍以纯文本呈现。Qt 不内置公式渲染引擎。
- **仅 Windows**：依赖 pynput 的 Windows 键盘钩子与 Qt `grabWindow` 的行为。
- **混合 DPI 多屏**：按主屏缩放比例换算框选坐标，150% 与 100% 混用时可能有几像素偏差。
- **「只看答案」不保证做对**：它只给最终结果，模型没有写过程的机会，因此比详细题解更容易出现算错而不自知。对答案场景建议扫一眼详细题解。
- **`keep_alive` 只对 Ollama 原生协议生效**：接口协议选「OpenAI 兼容」时该设置不生效，需用环境变量 `OLLAMA_KEEP_ALIVE`。
- **模型驻留常开会占显存**：设成「常驻不卸载」后模型一直占着显存，别的程序（游戏、绘图）可能因此变慢或报显存不足。
- **解答由大模型生成，可能出错**，请自行判断，不要直接当作标准答案。
- **不含搜题题库**：没有接入任何在线题库/搜索，纯模型解答。

## 十三、技术选型说明

- **Python + PySide6(Qt6)**：一套代码同时解决悬浮窗、置顶、无边框拖拽、截图遮罩、托盘、多显示器与高 DPI，比 Java 写 Swing/JavaFX + JNativeHook 的代码量和坑都少，后续扩展也更容易。
- **pynput**：纯用户态全局键盘钩子，**不需要管理员权限**。
- **httpx 同步流式**：跑在 `QThread` 里，避免把 asyncio 和 Qt 事件循环耦在一起，逻辑简单可控，出问题好定位。
- **SQLite + 单一数据目录**：便于整体清理，配合双向对账做到「不留孤儿文件」。
- **热键实现特意没用 `pynput.GlobalHotKeys`**：实测该 API 在本机 Windows 上 `start()` 正常、`running=True`，但按键回调永不触发（连 `<f9>` 单键都不行）。现采用官方文档的 `HotKey` + `Listener` 手工桥接写法，实测 `<ctrl>+<alt>+q`、`<ctrl>+<shift>+s`、`<alt>+<f8>`、`<ctrl>+<alt>+<f10>` 均能稳定触发。
